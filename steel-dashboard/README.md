# לוח ברזל מקצועי

לוח בקרה למלאי, צריכה והזמנות ספק של פריטי ברזל מקצועי (HEA, HEB, IPE, UPN,
שטוח, זוויות, עגול, מרובע ועוד), מחושב משלושה דוחות פריוריטי. קובץ HTML אחד,
בלי שרת ובלי תלויות.

## נתונים לא נכנסים לריפו

הריפו הזה ציבורי. קבצי הייצוא מפריוריטי וכל קובץ בנוי שמכיל נתונים כוללים
עלויות, ספקים ומחירים, ולכן `steel-dashboard/dist/`, `steel-dashboard/data/`
וקבצי `*.xls` מוחרגים ב־`.gitignore`. לא לבטל את ההחרגה.

## שימוש בלי לבנות כלום

פותחים את `steel-dashboard/src/dashboard.html` בדפדפן, לוחצים "טעינת קבצים
מפריוריטי" (או גוררים לחלון) ובוחרים את שלושת הדוחות. הקבצים נקראים רק
בדפדפן; הדפדפן זוכר את הטעינה האחרונה עד שלוחצים "חזרה לנתוני הדוח".

| דוח | שם הקובץ בדרך כלל | מזוהה לפי העמודה |
| --- | --- | --- |
| כרטיסי פריט | `parts.xls` | `ברזל_מקצועי` |
| מלאי ותמחור | `MlyTimhur3.xls` | `MACSAN` |
| הזמנות ספק פתוחות | `OpnOrdSup.xls` | `מס_הז` |

הדוחות הם קבצי טקסט מופרדי טאבים בקידוד windows-1255 (כך פריוריטי שומרת
"xls"). גם UTF-8 עובד. הסדר לא משנה.

## שתי תצוגות

- **תמונת מצב** (`#board`): מדדים, רשימות פעולה, משפחות, מחסנים, הגעות, ספקים,
  הזמנות פתוחות, כל הפרופילים ואיכות נתונים.
- **הזמנת יבוא** (`#order`): לכל חומר בוחרים חודש הגעה, עד מתי ההזמנה צריכה
  להחזיק וצעד עיגול. הדף מציע כמות לכל מק״ט, מקובצת לפי פרופיל, ומאפשר לשנות
  כל כמות. הטיוטה נשמרת (ב־Artifact: במסד הנתונים של הדף; בקובץ מקומי: בדפדפן),
  ואפשר להוריד אותה כ־CSV לאקסל או להעתיק.

## המלצות רכש

בראש דף ההזמנה, לפי סדר עדיפות: (1) להמיר שורות בהזמנות שעוד לא הועמסו
ושיש מהן יותר משנת מלאי, למידות החסרות אצל אותו ספק; (2) מה ייגמר לפני שיבוא
יכול להגיע, לרכש מקומי או הקדמה; (3) סיכום היבוא החדש; (4) שורות באיחור;
(5) פערי מחיר בין ספקים באותה משפחה; (6) מלאי בלי תנועה. החישוב ב־`recommend()`
ב־`model.js`.

## זמן אספקה

כלל עבודה: 5 חודשים מההזמנה להגעה, בשחור ובמגולוון (`DEFAULT_LEAD_MONTHS`).
ניתן לשינוי בדף ההזמנה ונשמר עם הטיוטה. החציון בפועל מההזמנות הפתוחות מוצג
לשם השוואה בלבד.

## טיוטת ההזמנה

נשמרת אוטומטית (ב־Artifact: במסד הנתונים של הדף; בקובץ מקומי: בדפדפן).
"שמירת טיוטה לקובץ" מוריד JSON, ו"טעינת טיוטה מקובץ" (או גרירת קובץ ה־JSON)
מחזיר אותה. הקובץ מכיל כמויות, חודשים וזמן אספקה, בלי נתוני מלאי.

## פרופילים ואורכים

UPN160 (6 מ׳) ו־UPN160-12 (12 מ׳) הם פרופיל אחד. האורך נלקח מסיומת המק״ט
(`-12`, `-12.1`, `-6`, `-3`) ואם אין, מהתיאור; מק״ט סיני (`C`, "סיני")
מצטרף לאותו פרופיל. כל הרשימות מוצגות לפי פרופיל, וכל אורך מוצג בנפרד בתוכו.

## מחסנים

מחסנים 99 (לא שלנו) ו־10 (בירורים, מלאי לא קיים) לא נספרים כברירת מחדל
(`DEFAULT_EXCLUDED_WH` ב־`model.js`). בתמונת המצב אפשר לסמן ולבטל כל מחסן.

## בנייה עם הנתונים בפנים

```bash
npm run steel:build -- parts.xls MlyTimhur3.xls OpnOrdSup.xls
# -> steel-dashboard/dist/steel-dashboard.html (מוחרג מ-git)
```

אפשרויות:

- `--out <file>` נתיב פלט אחר.
- `--fragment` בלי מעטפת `<!doctype>/<html>/<body>`, למארחים שמוסיפים אותה
  בעצמם.
- בלי קבצים: בונה לוח ריק שמחכה לטעינה בדפדפן.

## מבנה

```
steel-dashboard/
  src/model.js        פענוח הדוחות וכל החישובים (רץ בדפדפן וב-Node)
  src/dashboard.html  המסך: תבנית, עיצוב ורינדור
  build.mjs           מטמיע את model.js ואת הנתונים לקובץ אחד
```

`model.js` חושף `extract(texts)` שממיר את שלושת הדוחות לתמונת מצב מצומצמת
(רק פריטי ברזל מקצועי ורק השדות הדרושים), ו־`compute(snapshot, { material })`
שמחזיר את כל המדדים למסך.

## הגדרות החישוב

- **ברזל מקצועי**: `תאור_טיפוס_משפחת_מוצר = מקצועי` בכרטיס הפריט. הדגל
  `ברזל_מקצועי = Y` לא עקבי מולו, והלוח מציג את הפערים באיכות נתונים.
- **מלאי**: סכום `יתרה` בכל המחסנים והאיתורים; ערך = `ערך`.
- **צריכה חודשית**: `צריכה_חודשית` מדוח המלאי, ואם חסר, `ממוצע_יציאות`.
  תקופת הממוצע מוגדרת בפריוריטי ולא מופיעה בקובץ.
- **בדרך**: `טון_ית` בהזמנות פתוחות שאינן טיוטה. תאריך צפוי = `תא`
  (תאריך הגעה, ואם אין, תאריך אספקה).
- **זמן אספקה מיבוא**: 5 חודשים (כלל עבודה). לשם השוואה מוצג חציון (תאריך צפוי
  פחות `תא_הז`) בהזמנות במטבע זר.
- **להזמין**: פריט פעיל ש־(מלאי + בדרך) ÷ צריכה קטן מזמן האספקה מיבוא.
- **ייגמר לפני ההגעה**: צריכה × חודשים עד ההגעה הקרובה > מלאי.
- **הזמנות על עודף**: בהזמנה פתוחה למרות יותר מ־12 חודשי מלאי או בלי צריכה.
- **המלצת יבוא**: לכל מק״ט, מהאורך הארוך לקצר: מלאי בהגעה = מלאי + הזמנות
  שמגיעות עד אז − צריכה עד אז; צורך = צריכה מההגעה ועד היעד − מלאי בהגעה −
  הזמנות שמגיעות בתקופה. עודף באורך ארוך עובר לקצר (חיתוך), לא להפך. צורך של
  6.05 מ׳ מתווסף ל־12.1 מ׳ (6.05 נחתך מ־12.1, לא מיובא). מעוגל למעלה לצעד;
  צורך קטן מחצי צעד מסומן ולא מוזמן.
- **חוסר עד ההגעה**: צריכה עד חודש ההגעה − מלאי − הזמנות שמגיעות עד אז.
- **תאריך ייחוס** לכל חישובי "באיחור": תאריך הפקת דוח המלאי.
